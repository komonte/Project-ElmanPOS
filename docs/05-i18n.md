# 05. Internationalization (i18n)

## Overview

ElmanPOS uses a **server-side i18n** system. All UI strings are translated in Go before being sent as HTML to the browser. This ensures the system works fully **offline** — no browser translator or external API is needed.

## How it works

```
Browser request → LocaleMiddleware → WebHandler → html/template → translated HTML
```

1. **Language detection** — `internal/transport/locale.go` middleware reads the user's preference on every request:
   - Priority 1: Cookie `lang` (set by the language toggle in the UI)
   - Priority 2: HTTP header `Accept-Language`
   - Fallback: `"en"` (English)

2. **Template rendering** — `internal/transport/web/templates.go` parses all `.gohtml` templates **once per language** at startup, each with a `t(key)` function hardcoded to that language.

3. **In templates**: `{{ t "dashboard.title" }}` outputs the translated string directly.

## Translation files

Location: `backend/internal/i18n/`

| File | Language |
|---|---|
| `en.json` | English (default) |
| `es.json` | Spanish |

### Format

```json
{
  "app.title": "ElmanPOS",
  "nav.dashboard": "Panel",
  "common.save": "Guardar"
}
```

Keys use dot notation grouped by domain (`common.*`, `brand.*`, `tax.*`).

### Fallback chain

If a key is missing in the active language, the system falls back to English. If missing in English, the raw key is displayed.

## Adding a new language

1. Copy `en.json` → `fr.json` (or your language code)
2. Translate all values (keep the keys identical)
3. The new language is automatically:
   - Detected from `Accept-Language` headers
   - Available in the language selector dropdown
   - Parsed into templates at next startup

No code changes needed beyond the JSON file.

## Language switch (UI)

The navbar includes a `<select>` dropdown that triggers `POST /settings/language` with the chosen language code. The server sets a cookie and the page refreshes. The preference persists across sessions (cookie expiry: 1 year).

## Using translations in Go code

```go
import "github.com/komonte/Project-ElmanPOS/backend/internal/i18n"

// Direct lookup
str := i18n.T("es", "dashboard.title")

// Via request context (from middleware)
import "github.com/komonte/Project-ElmanPOS/backend/internal/transport"
str := transport.T(r.Context(), "dashboard.title")
```

## Files layout

| File | Purpose |
|---|---|
| `internal/i18n/en.json` | English translations |
| `internal/i18n/es.json` | Spanish translations |
| `internal/i18n/translator.go` | Loader + lookup + fallback logic |
| `internal/transport/locale.go` | Middleware: detects language per request |
| `internal/transport/web/templates.go` | Per-language template parsing with `t()` func |

## Architecture decision

Storing translations as embedded JSON files (via `//go:embed`) means:
- **Single binary** — no external files at runtime
- **No database dependency** — language preference is stored in a cookie, not in `app_settings`
- **Full offline capability** — no network calls for translation
- **Fast** — maps are parsed once at startup, lookups are O(1)
